### **Общая цель проекта:**
Разработать и оптимизировать NLP-модели для решения практических задач (классификация, генерация / RAG), применяя современные методы тонкой настройки и оптимизации для достижения баланса между качеством и скоростью работы.

---

### **Цель 1: Fine-tuning BERT-like модели для классификации текста**

**Конечный результат:** Готовая, оптимизированная модель, принимающая на вход текст и возвращающая его класс. Модель должна иметь обоснованные метрики качества и быть адаптирована для быстрого инференса.

**Шаги для достижения:**

1.  **Выбор модели и данных:**
    *   Выбрать конкретную предобученную BERT-модель (e.g., `cointegrated/rubert-tiny2`).
    *   Найти, скачать и провести первичный анализ датасета (количество примеров, баланс классов).
2.  **Подготовка данных:**
    *   Разделить данные на обучающую, валидационную и тестовую выборки.
    *   Написать код для токенизации текстов с использованием `BertTokenizer`.
    *   Создать объекты `Dataset` и `DataLoader` для эффективной подачи данных в модель.
3.  **Базовое обучение (Baseline):**
    *   Загрузить модель `BertForSequenceClassification`.
    *   Написать и запустить цикл обучения со стандартными гиперпараметрами (lr=2e-5, epochs=3-4).
    *   Рассчитать baseline-метрики (Accuracy, F1-score) на валидационной и тестовой выборках.
4.  **Подбор гиперпараметров и оптимизация:**
    *   Провести эксперименты по подбору learning rate, batch size и количества эпох для улучшения качества и скорости сходимости.
5.  **Квантизация и ускорение инференса:**
    *   Применить метод динамической квантизации (`torch.quantization.quantize_dynamic`) для конвертации модели в формат INT8.
    *   Замерить и сравнить: размер модели, скорость предсказания и точность до и после квантизации.
6.  **Финальная оценка:**
    *   Запустить финальную модель на тестовой выборке и зафиксировать результаты.
    *   Подготовить примеры работы модели.

### **Цель 2: Fine-tuning GPT-like модели или реализация RAG**

**Конечный результат:** Система, способная генерировать осмысленные текстовые ответы на основе заданной инструкции (запроса) либо путем тонкой настройки, либо путем извлечения информации из базы знаний.

**Шаги для достижения (два возможных пути):**

**Вариант 2A: Fine-tuning GPT-like модели**

1.  **Выбор модели и данных:**
    *   Выбрать языковую модель (e.g., `ai-forever/rugpt3large`).
    *   Найти датасет формата "instruction-response".
2.  **Подготовка данных:**
    *   Привести данные к формату, ожидаемому моделью (один длинный текст с разделителями между примерами).
    *   Реализовать шаблон промпта (e.g., `"Инструкция: {instruction}\nОтвет: {response}<|endoftext|>"`).
3.  **Эффективное обучение:**
    *   Использовать технику **LoRA** (Low-Rank Adaptation) для быстрой и эффективной настройки, чтобы не обучать все миллиарды параметров.
    *   Провести обучение, подобрав learning rate (~1e-5).
4.  **Оценка качества:**
    *   Оценить качество генерации по метрикам ROUGE/BLEU и через субъективную оценку релевантности и связности ответов на тестовых промптах.

**Вариант 2B: Реализация RAG (Retrieval-Augmented Generation)**

1.  **Подготовка базы знаний:**
    *   Взять набор документов (датасет), который будет выступать в качестве source of truth.
    *   Разбить документы на небольшие перекрывающиеся чанки.
2.  **Настройка Retriever'а:**
    *   Выбрать модель для получения векторных представлений (эмбеддингов) текста (e.g., `sentence-transformers`).
    *   Рассчитать эмбеддинги для всех чанков и сохранить их в векторной базе данных (e.g., FAISS).
3.  **Настройка Generator'а:**
    *   Выбрать большую языковую модель (можно даже нулевого-shot, вроде `ChatGPT` или `rugpt3` без дообучения).
4.  **Построение конвейера:**
    *   Написать код, который:
        *   Получает вопрос пользователя.
        *   Находит в векторной базе `k` наиболее релевантных чанков.
        *   Формирует промпт вида: `"Используй только информацию ниже:\n{чанк_1}...\n\nВопрос: {вопрос}\nОтвет:"`.
        *   Подает промпт в языковую модель и возвращает сгенерированный ответ.
5.  **Оценка системы:**
    *   Оценить точность и релевантность ответов, а также способность системы не "галлюцинировать".

### **Сквозная цель: Оптимизация и инженерия**

**Конечный результат:** Все модели должны быть не только точными, но и быстрыми, с возможностью их развертывания.

**Шаги для достижения:**

1.  **Квантизация:** Применить для всех моделей (где возможно) для сокращения их размера и ускорения работы.
2.  **Чистый код:** Оформить код в виде читаемых скриптов и/или Jupyter-ноутбуков с комментариями.
3.  **Документация:** Написать README файл с инструкцией по запуску и выводами по результатам работы (метрики, размер моделей, время инференса).
4.  **Подготовка отчетности:** Создать финальный отчет или презентацию, где наглядно сравниваются результаты задач, делаются выводы об эффективности примененных методов оптимизации.
